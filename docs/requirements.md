## 機能要求

| ID | 要求 | 受け入れ条件（初案） | 状態 |
|---|---|---|---|
| REQ-INPUT-001 | 複数のHIDデバイス入力を組み合わせられること | 対象デバイスとイベントを識別して処理できる。対象デバイス一覧と識別方法は要検討 | 未検証 |
| REQ-BIND-001 | 特定の入力を別の入力動作や機能切替に割り当てられること | 設定されたバインドに従って動作する。設定形式・競合時の規則は要検討 | 未検証 |
| REQ-MOD-001 | あるデバイスの修飾キー状態を別デバイスの入力処理に利用できること | デバイス横断の修飾キー状態が定義済みルールに従う。押下・解放・同時入力規則は要検討 | 未検証 |
| REQ-PASS-001 | 変更対象外の通常入力を通過させること | 対象外入力が意図せず抑制・重複・変換されないことを実機で確認する | 未検証 |
| REQ-ARCH-001 | ドライバ部分とアプリ部分を分離すること | 入力フック・イベント受け渡しと、修飾キー／バインド処理の責務が分離されている | 設計中 |
| REQ-QUEUE-001 | 入力イベントを構造化してキューに渡すこと | デバイス識別子、キー、イベント種別等を含むイベント構造とキューの契約を定義する | 設計中 |
| REQ-DOC-001 | 仕様書・設計書をMarkdownで管理すること | 文書がGitでバージョン管理される | 対応中 |
| REQ-TRACE-001 | 要求・仕様・設計・コード・テストを追跡できること | トレース表で各IDと実装・テストの対応を示す。未対応項目も明示する | 対応中 |
| REQ-PLAN-001 | 工程を管理すること | 工程計画とGitHub Issuesの責務を定義し、作業状況を更新する | 対応中 |

## 非機能要求・品質目標

| ID | 要求 | 受け入れ条件 | 状態 |
|---|---|---|---|
| REQ-PERF-001 | 入力処理の遅延を抑える | 測定方法と許容値を決め、実機で測定する。数値目標は要検討 | 要検討 |
| REQ-ROBUST-001 | キーの押下・解放状態を安全に扱う | キー解放漏れ、同時入力、デバイス切断、異常終了の試験を行う | 未検証 |
| REQ-DIAG-001 | 問題調査に必要な診断を可能にする | 個人情報や入力内容を過剰に記録しない診断方針を定義する | 要検討 |

## 制約・前提

- 想定言語：AutoHotkey v2。
- HIDフック関連ライブラリ：AutoHotInterception（AHI）。
- 想定OS：Windows（具体的な対応バージョンは未確定）。
- 実装方式、AHIバージョン、イベント構造、スレッド／キューの具体方式は技術検証後に確定する。

## 要確認事項

1. 対応する Windows、AHK v2、AHI のバージョン。
2. デバイスを安定して識別する方式と、同型デバイスが複数ある場合の扱い。
3. 通常入力を通過させる場合と、置換・抑制する場合のフック制御。
4. キューの実装方式、スレッド安全性、満杯時の挙動。
5. 修飾キーの共有範囲、左右デバイス間の押下・解放・競合規則。
6. 設定ファイル形式、設定の再読み込み、設定不備時の動作。
7. 遅延・CPU使用率などの測定基準。
