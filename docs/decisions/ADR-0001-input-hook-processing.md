# ADR-0001：入力フック処理と後段キューの境界

- 状態：提案中（未決定）
- 日付：2026-10-18
- 関連要求：REQ-PASS-001, REQ-QUEUE-001, REQ-PERF-001
- 関連設計：DES-HOOK-001, DES-QUEUE-001

## 背景

本プロジェクトは、AHIから複数デバイスの入力を受け取り、構造化イベントをキュー経由でアプリ側へ渡す構成を目指す。一方、通常入力の通過と、変換対象入力の抑制・置換には、フック処理のタイミングが影響する可能性がある。

## 検討する選択肢

1. **フック側で最小限の同期判断を行い、後段へ処理を渡す。**
   - 長所：通過／抑制判断が必要な場合に間に合う可能性がある。
   - 短所：フック内の判断ロジックと設定の扱いが複雑になり得る。
2. **全判断をイベントキューの後段で行う。**
   - 長所：アプリ側の処理を分離しやすい。
   - 短所：元入力を抑制する必要がある場合、判断が遅すぎる可能性がある。
3. **用途に応じて同期判断と後段処理を組み合わせる。**
   - 長所：時間制約のある処理と複雑な処理を分離できる可能性がある。
   - 短所：境界と状態同期の設計が必要。

## 決定

未決定。AHIの採用バージョンで最小プロトタイプを実装し、通常入力の通過、対象入力の抑制・置換、イベント順序、処理遅延を検証してから決定する。

## 決定に必要な証拠

- 使用したAHI／AHKのバージョン
- 再現可能な最小コード
- 通過・抑制・置換それぞれの結果
- イベントの順序・遅延・負荷に関する測定
- 検証に基づく選択肢比較

## 影響

このADRが決まるまでは、キュー方式、スレッド構成、フック内の責務を最終確定しない。検証結果を受けて本文を更新し、状態を「採用」または「却下」に変更する。
