# 設計書

- 文書ID：DES-DOC-001
- 状態：初版・技術検証前

## 1. 設計原則

- 入力フックの責務とアプリケーションのルール処理を分離する。
- イベント形式と各モジュールの境界を明示する。
- 共有状態へのアクセス方法を明確にし、同時入力時の競合を避ける。
- 入力を抑制・置換する必要がある場合、フック処理のタイミング制約を優先して設計する。
- 実機で確認できていないAPI挙動や性能を前提にしない。

## 3. ドライバ部とアプリ部

### ドライバ部

- AHIから入力イベントを受け取る。
- デバイス識別子とイベント情報を正規化する。
- フック内で同期的に決定しなければならない処理と、後段へ渡せる処理を分離する。
- フックコールバック内で重い処理や不必要な待機を行わないことを設計目標とする。

### アプリ部

- 受け渡されたイベントを処理する。
- 修飾キー管理とキーバインド解決を別モジュールにする。
- 設定と診断を入力処理の中心ロジックから分離する。
- 「キューを高速に監視する」具体方式は、AHK v2の機能と測定結果に基づいて決定する。ポーリングを採用すると決めたわけではない。

## 4. イベント構造（概念案）

| フィールド | 意味 | 状態 |
|---|---|---|
| deviceId | デバイス識別子 | 取得方法要検証 |
| inputCode | キー／ボタン等の入力コード | 型要検討 |
| eventType | down / up 等 | 要定義 |
| sequence / timestamp | 順序または時刻情報 | 必要性要検討 |
| sourceData | 必要な場合の元イベント情報 | 最小限に限定 |

## 5. キューとフック処理の境界

非同期キューを通じて後段処理を行う設計を候補とする。ただし、対象入力をOSへ通過させるか抑制するかをフック内で即時に決める必要がある場合、後段での判断は間に合わない可能性がある。

したがって、最初に小さなプロトタイプで以下を検証する。

1. AHIのコールバックでイベントを取得できる条件。
2. 通常入力を通過させる仕組み。
3. 特定入力を抑制・置換する仕組みと、その判断タイミング。
4. 後段へイベントを渡す際の遅延・順序・競合。
5. AHK v2で利用可能な同期／キュー方式。

## 6. エラー処理と安全策（要設計）

- 初期化に失敗した場合の通知と終了方針。
- 設定不備時に入力を危険な形で変換しない方針。
- キー解放漏れを検出・回復する方法。
- デバイス切断時の修飾キー状態のリセット。
- 診断ログに機微な入力内容や不要なデバイス識別情報を含めない。

## 7. トレースタグの書式

実装コメントは必要な箇所に限り、次のように要求・仕様・設計IDを参照する。

```ahk
; MOD-DRIVER-001
; Implements: SPEC-INPUT-001
; Related: REQ-PASS-001
```

コードが存在しない段階では、例示用タグであり、実装済みを示すものではない。
