# AHKTS — 複数HID入力統合ラッパー

AutoHotkey v2（AHK）と AutoHotInterception（AHI）を利用し、複数のHID入力デバイスを組み合わせて、入力の切り替えやデバイス横断の修飾キー操作を実現することを目指すプロジェクトです。

## 目的

- フットスイッチ、マウス、複数キーボード、テンキーなどの入力を組み合わせる。
- 例：フットスイッチでテンキーの機能を切り替える。
- 例：右手側キーボードの修飾キーを押しながら、左手側キーボードの入力動作を変える。
- 要求、仕様、設計、実装、テストの対応関係を追跡できるようにする。

## 開発方針

- ドライバ部分とアプリ部分を分離する。
- ドライバ部分は AHI のフックを受け、デバイス識別子、キー、イベント種別などを構造化してキューに渡す。
- アプリ部分はキューを処理し、修飾キー管理とキーバインド処理を分離する。
- 仕様書・設計書は Markdown で管理する。
- 要求・仕様・設計・モジュール・テストに追跡用IDを付ける。
- 実機で確認していない挙動は、確定事項として扱わない。

## 開発環境・依存関係

- Windows
- AutoHotkey v2
- AutoHotInterception（AHI）

AHIの元のリリースZIPは `third_party/archives/` でGit管理し、展開物は `vendor/` に生成します。`vendor/` はGit追跡対象外です。取得元、バージョン、ハッシュ、ライセンス確認状況、展開手順は [依存関係の管理](docs/dependencies.md) を参照してください。

依存物のアーカイブは、ライセンスと再配布条件を確認してから追加してください。現段階では、AHIの採用バージョン、対応環境、動作保証を確定していません。

## 開発状況

初期文書整備段階です。最初の技術検証では、AHIフックでの入力受信、通常入力のパススルー、対象入力の抑制・置換、処理タイミングの制約を確認します。

## 作業の進め方

1. GitHub Issue に目的、完了条件、関連IDを記録する。
2. 文書・コードの変更を行い、関連するトレース表とテスト仕様も更新する。
3. Pull Request で差分と検証結果を確認する。
4. 実機でのテスト結果を記録し、必要に応じて CHANGELOG と Release を更新する。
